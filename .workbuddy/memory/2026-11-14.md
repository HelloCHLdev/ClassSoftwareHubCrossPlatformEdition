## 修 CI + 加自动发 Release

### 怎么读 GitHub Actions 日志（不用 gh CLI）

本机没装 `gh`，但钥匙串里有凭证：

```bash
TOKEN=$(printf "protocol=https\nhost=github.com\n\n" | git credential fill | sed -n 's/^password=//p')
curl -sL -H "Authorization: token $TOKEN" \
  -o job.log "https://api.github.com/repos/<owner>/<repo>/actions/jobs/<job_id>/logs"
```

- `actions/jobs/{id}/logs` 匿名访问返回 403（"Must have admin rights"），带 token 就行。
- `check-runs/{id}/annotations` 只能拿到 "Process completed with exit code 2" 这种没用的信息，
  真正的报错要看 job 日志。
- 匿名调 API 会很快撞 rate limit，一律带 token。

### 踩到的 4 个坑

1. **bash 3.2 和 5.x 的行为差异（本地测不出来）**
   `${VER//-/~}` 在 macOS 自带的 bash 3.2 上是 `1.0.0~ci.xxx`，
   在 Ubuntu runner 的 bash 5.x 上 `~` 被展开成 `$HOME` → `0.0.0/home/runnerci.xxx`，
   dpkg-deb 直接报 `invalid character in version number`。
   → 一律用 `tr '-'` `'~'`（两边行为一致）。
   → `${VER//-/\~}` 也不行：bash 3.2 会留下字面反斜杠。

2. **`rm -rf "${DIST}"` 之后忘了 `mkdir -p "${DIST}"`
   → `dpkg-deb: error: unable to create 'dist/xxx.deb': No such file or directory`。
   macOS 那段有 `mkdir -p "${DIST}"`，Linux 漏了。本地测试时目录里恰好有 `dist/`，
   所以没暴露。**以后测打包脚本要在全新空目录里跑。**

3. **GitHub 上传 Release 资产时会把文件名里的 `~` 换成 `.`**
   → deb 资产叫 `xxx_0.0.0.ci.xxx_amd64.deb`，而 checksums.md5 里写的是
   `xxx_0.0.0~ci.xxx_amd64.deb`，`md5sum -c` 对两个 deb 直接失败。
   → 上传前自己先把 `~` 换成 `.`（跟 GitHub 的行为对齐）。

4. **`push: branches` 不匹配 tag 推送**
   只有 `branches: ['**']` 的话，推 tag 根本不会触发构建。

### Release 发布规则（最终版）

在 `build.yml` 里加 `release` job（`needs: build`），并删掉了原来的 `release.yml`
（发布逻辑并进 build.yml，避免同一个 tag 发两次）：

| 触发 | Release tag | 标记 |
|---|---|---|
| push 任意分支 | `v0.0.0-ci.<sha 前 7 位>` | prerelease |
| push `v*` tag | 该 tag | 版本带 `-` 才 prerelease |
| pull_request | 不发（fork 不能往仓库塞 Release） | — |
| 手动 dispatch | 同分支推送，可关掉 | — |

- 发布说明取仓库里的 `CHANGELOG.md`（`.md`/`.MD` 两种写法都找，因为 Linux 大小写敏感）；
  找不到或为空时自动生成摘要兜底。
- 产物附 `checksums.md5`（md5sum 二进制格式，和应用内更新器对得上）。
- `concurrency.cancel-in-progress: false`：每次推送都发 Release，中途取消会留下
  资产不全的 Release。

### 为什么不能用滚动 tag（`latest`）

`Services/Updating/UpdateModels.cs` 的 `VersionCompare` 会把 Release 的 tag 当版本号比大小
（会剥掉 `v` / `dv` 前缀）。滚动 tag `latest` 会被当成字符串，
`Compare("latest", "1.0.0")` 结果是 "latest 更新" → 用户会收到假更新。
所以每次构建各发一个带真实版本号的 Release。

`GitHubReleaseSource` 按 `prerelease` 字段分流：Stable 通道跳过预发布，
Insider 通道才收 → CI 快照不会污染正式版通道。

5 个平台全绿，Release 正常产出，checksums 与资产名一一对应。
